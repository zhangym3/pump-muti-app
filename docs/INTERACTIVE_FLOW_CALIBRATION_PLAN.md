# 人工计量式流量校验优化方案

状态：功能代码已实现。2026-10-22 软件测试与固件构建通过；低档单节点台架测试未收到 Hall 脉冲，APP 真机 BLE 与计量精度验收未完成。

## 目标

把设置页的三档流量校验改为受控的人工计量流程：选择一个从机和速度档，输入标准水量；启动后让主机水泵和该从机阀门出水；人工计量开始时记录从机脉冲基线；人工计量完成时停止出水并取得结束脉冲；按标准水量计算该档系数。

计算使用计量开始与停止之间的脉冲差：

```text
delta_pulses = stop_pulses - begin_pulses
系数（脉冲/mL） = delta_pulses / standard_ml
固件 K（脉冲/升） = round(delta_pulses * 1000 / standard_ml)
```

例如标准水量为 500 mL、计量区间脉冲差为 2940，则 APP 显示 5.880 脉冲/mL，主机保存 K=5880。保存精度到 0.001 脉冲/mL；显示精度不代表实际测量精度。

## 当前实现

- APP 设置页提供从机、速度档和标准水量选择，并实现启动预出水、确认计量基线、停止结算、结果预览和当前档系数保存；会话可查询恢复。
- 主机持久化校验会话身份和请求序号，限定一个在线从机；从机启动确认后才启动公共水泵，停止时先停泵再关闭目标阀门。
- 从机在计量开始时确认脉冲基线；校验任务旁路旧 K 推算的目标脉冲，但继续保留租约、联锁、无流和最大运行时间保护，并回报停止值与尾流终态。
- 零脉冲、尾流不稳定、超时、传输故障和身份不匹配的样本不可保存。`cal-set` 保留另外两档读回值及现有 revision/baseK/baseVersion 冲突检查。

## 用户操作流程

校验只允许一次操作一个在线且已启用的从机。开始前读取该节点现有三档系数，并确认主机速度档已生效。

| 状态 | 用户操作 | 系统行为 |
| --- | --- | --- |
| 配置 | 选择从机、低/中/高档，输入标准水量 | 校验输入范围，显示节点地址和主机当前速度确认状态；配置在本次会话期间锁定 |
| 待启动 | 点击“启动抽水” | APP 请求主机创建校验会话；主机单播准备并打开目标从机阀门，收到从机启动与租约确认后才启动水泵 |
| 预出水 | 将水引入废水容器，待流动稳定 | 显示“预出水，尚未计入”；此时脉冲不计入本次校验样本 |
| 计量中 | 人工开始计量时点击“开始计量” | 主机请求从机原子记录当前任务脉冲基线；收到从机确认后才开始显示计量中和累计脉冲 |
| 停止中 | 人工计量达到输入水量时点击“停止” | 主机立即关闭水泵并单播关闭阀门；从机在处理停止时锁定计量终点，并完成安全尾流结算 |
| 结果 | 收到匹配会话的从机终态结果 | APP 以从机确认的起止脉冲差计算当前档系数；显示水量、速度、脉冲差、耗时、尾流脉冲和有效性 |
| 保存 | 用户确认“保存当前档系数” | 保留另两档读回值，使用现有 revision/baseK/baseVersion 规则提交三档；收到主机确认后显示已保存 |

建议首版水量范围沿用普通任务的 50–2000 mL，默认 500 mL。后续可依据低档实际流速和所需测量精度调整。预出水必须有明确提示，避免用户把未计入的水误认为校验样本。

## 会话与消息设计

数据路径保持为 `APP → BLE GATT 主机 → 单播 Mesh 从机`，结果由主机经 GATT 通知 APP。校验不直接连接从机，不向 Mesh 组地址广播。

APP 与主机之间新增有身份和序号的校验会话操作：启动、开始计量、停止、查询。所有操作带本次主机 epoch、客户端请求序号和校验会话 ID；启动请求持久化去重，连接中断后只查询原会话，不自动新建或重启。

Mesh 侧复用已有的单播准备、启动、租约、进度、关闭和终态结果机制；增加一个从机确认的“记录计量基线”动作。校验任务使用明确的 manual-calibration 标记，不依赖任何现有 K 计算目标脉冲，也不因达到旧系数推算的脉冲数自动关阀。停止结果至少关联会话 ID、节点地址、计量起点、停止时脉冲、终态脉冲、尾流脉冲、运行时间和停止原因。

进度仍可复用已有从机到主机的单播脉冲上报和主机到 APP 的 `LIVE` 通知。起点必须由从机确认，终点以停止处理时从机锁定的脉冲值为准；APP 上最后一条 2 秒周期进度不能代替终态数据。

保存继续使用现有 `cal-get` / `cal-set` 协议和主机 NVS。只覆盖被测档位，未测档位保留已读值；保存确认必须匹配节点地址、基础 K/版本、校验版本和三档返回值。

## 状态、安全和异常处理

- 校验期间禁止启动普通任务、独立试泵、改变速度、切换目标从机、组网、删除或启用从机以及保存其他校准值。
- 保留从机本地互锁、租约、无脉冲检测和最大运行时间保护。校验模式只关闭“到达计量目标脉冲自动关阀”，不关闭其他安全保护。
- 校验运行必须有硬超时。建议首版默认 60 秒，由主机 MCU 计时；到时自动停泵、关闭阀门并把结果标为超时无效。实际值需按最低档流速实测确认。
- “停止”入口始终可用。主机收到停止后先停止公共水泵并发送目标从机关闭命令；从机最终结果未确认时显示“结果待核实”，允许查询，不自动重启或保存。
- 断连、Mesh 传输故障、节点重启、组网状态变化、存储异常或结果身份不匹配时，立即进入停止/对账路径。无法证明泵阀已关闭或结果不完整时，不生成可保存系数。
- 零脉冲、计量区间过短、系数超出 0.001–1000.000 脉冲/mL、用户取消、无流或尾流未稳定，都标记为无效，不改写已保存系数。
- 收到停止后用于公式的终点应与 UI 的人工计量结束语义一致。终态还应单独报告关阀后的尾流脉冲，供用户判断样本是否有效；不得把显示进度的延迟脉冲悄悄并入另一个时间区间。

## 主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 人工按键反应时间及 BLE/Mesh 传输延迟造成起止误差 | 起点/终点由从机确认并锁定；增加运行耗时和尾流数据；用重复实测评价稳定性 |
| “启动抽水”到“开始计量”之间已有水流 | 明确显示预出水状态并提示导入废水容器；基线由从机记录，忽略预出水脉冲 |
| 旧 K 影响校验结果 | 校验模式不按 K 计算停止目标，只将设置水量用作最终系数计算的分母 |
| 单路校验误开多个阀或未开阀只运行水泵 | 主机只接受一个已登记节点；收到目标阀启动和租约确认后才允许水泵输出 |
| 低脉冲样本受量杯刻度和整数舍入影响 | 采用足够大的样本量；每档建议至少重复 3 次并显示各次结果；精度门槛由产品要求明确 |
| 保存超时导致手机与主机状态不一致 | 保存不自动重发；重连后重新读取主机值，再决定是否保存 |

该算法将输入的标准水量视为人工测量得到的水量。若用户只输入一个预设数值，却没有在停止时实际量到该水量，系数会按输入值产生系统偏差。因此结果页应明确显示“标准水量由用户确认”，并建议记录实际量杯读数用于验收；如产品要求结果完全由设备闭环确认，需要另行增加称重/量筒传感器，不能由脉冲数自行证明实际毫升数。

## 实施顺序

1. 固定从机校验会话的数据契约、manual-calibration 标记、基线确认和终态结果格式；确定主机 epoch、会话 ID、超时和去重规则。
2. 从机实现 manual-calibration 会话：原子记录基线、无目标脉冲自动停止、接收停止后关闭阀门并回传锁定脉冲与尾流结果；原有安全保护保持有效。
3. 主机实现单节点会话编排：确认阀门后启泵、租约续期、开始计量标记、停止优先级、结果对账和断连恢复。
4. APP 设置页加入水量、档位、启动/开始计量/停止/查询、结果预览及当前档保存；校验会话状态跨标签和 Activity 重建恢复。
5. 完成协议单测、APP 状态/UI 测试、主从机模拟测试，再在受控台架逐档验证。固件与 APP 版本能力不匹配时禁用校验入口。

## 本轮实施与验收记录

### 用户补充的水泵线序

用户提供的泵体图片标注型号 B24-12、DC 24 V、PWM 调速，并标明红线为 24 V 正极、黑线为负极、蓝线为 PWM 调速输入、黄线为转速反馈输出。图片没有标注 PWM 频率、输入高低电平/极性、黄线输出拓扑与电压上限、每转脉冲数。当前主机只在 GPIO4 输出暂定 20 kHz PWM，没有接入黄色转速反馈；APP 的档位和 `PUMP_PWM` 状态表示输出命令，不代表泵的实测转速。接入黄线前需取得泵规格或实测其电气特性，并确认电平适配，不能把未验证的反馈线直接接入 ESP32 GPIO。泵的转速反馈也不等于从机 GPIO5 的霍尔流量脉冲，不能单独证明实际流量。

## 验收门槛

- UI 状态顺序正确；未收到从机基线确认前不能显示“计量中”，停止操作在任何运行阶段都可触发。
- 仅目标地址收到校验控制；第二个从机没有阀门动作；公共水泵只在目标阀启动确认后输出。
- 起点前脉冲不计入，起点后到从机停止锁定点之间的脉冲计算准确；尾流单独显示；保存结果和终态记录使用同一差值。
- 达到旧 K 推算目标不会自动关阀；超时、无流、租约丢失、互锁和传输故障均能关闭泵阀且不能保存无效样本。
- 保存只改变当前档位，另外两档不变；主机重启后读回值一致；冲突版本、超时和断连都要求重新读值确认。
- 低、中、高档各完成不少于 3 次量杯测试，记录均值、最大偏差、标准水量、脉冲差和尾流。业务精度容差当前未定义；在容差明确并通过台架验收前，只能验收流程与协议，不能宣称计量精度达标。
